## Why this matters

`rahlwes.eu` still serves the old Squarespace site; the new site runs on `next.rahlwes.eu` and
must replace it. The cutover touches a **hostname that is hard-coded in five places**, plus DNS,
the Squarespace site and mail links. Some of those places fail silently: the newsletter's
confirmation, unsubscribe and `List-Unsubscribe` links are built from a constant
(`SITE_ORIGIN`), so if it is forgotten, every mail sent after launch links to the **staging**
host, and a staging outage would break unsubscribing (a legal requirement). Search ranking
depends on the 301 redirect map, which resolves on staging today but has never been checked
against the real production origin. This plan turns the cutover into one command that fails
loudly on anything left over, and prepares (but does not perform) the switch.

## Steps

### Step 1: Write the verification script

Create `scripts/verify-origin.mjs`: plain ESM, no dependencies, header comment explaining that
it checks a **running** origin and why (the build cannot prove DNS, redirects or mail links).

Usage: `node scripts/verify-origin.mjs <origin> <staging|production>`.

It must fetch from the given origin and report, per check, `PASS`/`FAIL` with the detail; exit
`1` if any check fails, `0` otherwise. Checks (each is one function, listed with the exact
expectation for each mode):

1. **robots.txt** — `GET /robots.txt`.
   staging: body contains `Disallow: /` and no `Allow: /`.
   production: body contains `Allow: /` and a `Sitemap:` line whose host equals the origin's host.
2. **noindex meta on the home page** — `GET /`, look for `<meta name="robots" content="noindex`.
   staging: present. production: **absent**.
3. **canonical and hreflang host** — the home page `<link rel="canonical" href>` and every
   `<link rel="alternate" hreflang>` must use the origin's host (no other host).
4. **sitemap hosts** — `GET /sitemap-index.xml`, follow each `<loc>`, require every `<loc>` host
   equals the origin's host; require at least 60 URLs in total (today: 67); require **no**
   URL containing `/admin` or `/keystatic`.
5. **legacy redirects** — for each path in the list below, `GET` with `redirect: 'manual'`,
   require status 301 or 307 or 308 (or 200 for `/newsletter`), follow redirects, require a
   final `200` and a final URL on the origin's host:
   `/journal`, `/journal/google-arts-and-culture`, `/journal/schwieriges-erbe`,
   `/journal/gab-es-zwangsarbeit-whrend-des-nationalsozialismus-in-frankfurt`,
   `/journal/digitale-spiele`, `/journal/orteerforschen`, `/journal/familienerforschen`,
   `/journal-en`, `/journal-en/the-frankfurt-history-app`, `/leistungen`, `/uebermich`,
   `/newsletter`, `/ausstellung-forschung`, `/nachgefragt`, `/familie-frank`,
   `/provenienzforschung`, `/digitales-storytelling`, `/unterrichtsmaterial`, `/nal`, `/museen`.
   (These 20 are the old Squarespace sitemap, read on 2026-11-17.) Also `/sitemap.xml` (after step 3).
6. **legal pages** — `/impressum/` and `/datenschutz/` return 200.
7. **mail links** — read `src/newsletter/email.ts` **from the file system** (not over HTTP), extract the
   `SITE_ORIGIN` string with a regex `SITE_ORIGIN\s*=\s*'([^']+)'`, and require it to equal the
   origin being verified. This is the check that catches the silent failure described above.
8. **security-relevant config** — read `wrangler.jsonc` as text and require that the string
   `"pattern": "<host>"` for the origin's host is present in `routes`.
9. **truncated descriptions** — `GET` the home page and three project pages; require no
   `<meta name="description" content="…">` value ending in `…` or `...` (the cut-off that plan 006 fixes).
10. **contact form is not fail-open** — `POST /api/kontakt` with body `null` and header
    `origin: <origin>`; require status `400` (proves plan 002's body check) — this request
    sends **no mail**.

Keep each check independent: one failing check must not stop the others.

**Verify**: `node scripts/verify-origin.mjs https://next.rahlwes.eu staging` → exit 0 on the
current staging (every check passes **except** possibly 9 until plan 006 lands and 10 until plan
002 is deployed; record which). Run
`node scripts/verify-origin.mjs https://next.rahlwes.eu production` → exit 1, with failures on
checks 1, 2, 3, 4, 7, 8. That **proves the script discriminates**; paste both outputs.
